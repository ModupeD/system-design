      Why do runtime calls go outward while imports point inward?

      Runtime PlaceOrderServicecalls → PaymentGatewaydispatches to → FakePaymentGateway
      Source PlaceOrderServiceimports → PaymentGateway← imports & implements FakePaymentGateway

      PlaceOrderService needs a payment to happen, so at runtime the call travels out of the core. But the core can't import an adapter, because then the business logic would depend on infrastructure. So the core defines the interface it needs (PaymentGateway), and the adapter imports that and implements it. The source-code arrow on the adapter side is reversed relative to the call: that's dependency inversion. The composition root (buildApp()) is the one place that connects the two at startup; that's dependency injection.
